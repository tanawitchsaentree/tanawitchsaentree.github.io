## Overview

A commercial claims platform at a leading European insurer, multi-line and high-complexity, with six-figure reserves per case, spanning marine, property, liability, cyber, and engineering lines. It's the kind of system where a misaligned button state isn't UX debt; it's a legal exposure.

The job was design systems lead. The job changed shape. I began delivering production-ready features straight from the ticket instead of handoff files. Nobody asked me to. I decided the output needed to change.

## What I Built

- FNOL (First Notice of Loss) wizard, sections and coverage review, closure automation, claim reopen, notes, financial overview, restrictions, activities log, payment and provider modals. Nine features in four months, each shipped from ticket to live in one session
- Established an audit → build → verify loop where no single pass does more than one thing: audit reads, build writes, verify runs the app and screenshots the evidence
- Extracted every failure pattern into a skill library loaded before each new session, so the same six debugging rounds don't repeat

## The Outcome

Features shipped the same day tickets arrived. The prototype became the backend API contract. The backend team designed their schemas from what the running interface showed, and the design artifact was the running software.
